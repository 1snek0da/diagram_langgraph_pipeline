# Sites V2 Web 前端接入设计

## 目标

将 `Trading Analysis UI Design` 的 Sites 版本 2 作为唯一正式前端基准，接入当前项目已有的 FastAPI Router 与 PostgreSQL。六个页面的视觉、布局、组件和交互尽量原样保留；只修改真实数据连接以及加载、空数据和错误状态。

## 已确认事实

- Sites 项目 ID：`appgprj_6a603dbc97408191ae68ca4e0aa2e74d`。
- 基准版本：版本 2，源提交 `b54f8ff76604c80b0974ab4d8a62a2804ce14095`，归档包含 39 个文件。
- GitHub 仓库中的两个 ZIP 都不包含独立 Web 前端：大包是旧 Python/MySQL 项目，小包是 FastAPI + Streamlit 接入包。
- 当前隔离树已经具备 FastAPI、任务 Router、PostgreSQL 迁移、六页所需的数据接口以及 Streamlit 调试界面。
- Streamlit 不再是正式产品界面，但在新前端验收完成前保留，便于调试和回退。

## 架构

```text
浏览器
  -> Sites V2 原版 Web 前端
  -> 同源 /api/v1 请求
  -> FastAPI Router
  -> 任务服务与 LangGraph
  -> PostgreSQL
```

前端不得直接连接 PostgreSQL，也不得持有数据库用户名或密码。所有数据库读写都由 FastAPI 完成。

## 仓库布局

```text
frontend/                 Sites V2 前端源码
src/diagram_langgraph_pipeline/
  api/                    现有 FastAPI 应用与 Router
database/                 现有 PostgreSQL schema 与迁移
streamlit_app.py          暂时保留的调试入口
```

不得把 Sites 项目当成新站点重新设计，也不得用 Streamlit 控件替换其组件。若 Sites 源码的工具链与上述目录约定冲突，保留其原始工具链，只把项目根目录调整到 `frontend/`。

## 页面与数据契约

| 页面 | 保留内容 | 真实数据来源 |
|---|---|---|
| 研究工作台 | 原统计区、最近任务与快捷入口 | 运行列表及状态汇总 |
| 新建分析 | 原任务类型、证券与参数表单 | 任务类型目录、创建分析接口 |
| 运行任务 | 原流程图、节点进度和状态反馈 | 单次运行详情与节点列表 |
| 行情视图 | 原行情图表与指标布局 | 行情图表接口 |
| 研究报告 | 原报告阅读与导出交互 | 报告详情接口 |
| 历史记录 | 原筛选、列表与跳转交互 | PostgreSQL 持久化运行列表 |

现有 API 可以满足的字段直接映射。若原界面需要而现有 API 缺失字段，优先在 FastAPI 响应模型增加向后兼容的只读字段；不得在前端伪造看似真实的财务数据。

## 前端数据层

- 建立单一 API 客户端，基础路径固定为同源 `/api/v1`。
- 开发环境通过前端代理转发到 `http://127.0.0.1:8000`，不在组件中硬编码端口。
- 页面组件只消费类型化的数据模型，不直接拼接网络请求。
- Sites 原有模拟数据仅可用于显式标注的视觉开发测试；正式构建不得回退到模拟数据。
- 路由之间通过运行 ID 等稳定标识传递上下文，刷新页面后应能根据 URL 恢复页面。

## 运行与部署

开发阶段：

- FastAPI 独立运行，负责 API 与 PostgreSQL。
- 前端开发服务器独立运行，提供热更新并代理 `/api/v1`。

正式阶段：

- 前端先生成静态生产构建。
- FastAPI 在 `/api/v1` 继续提供 API。
- FastAPI 在 `/` 提供前端构建，并对非 API 的未知路径回退到前端入口，以支持客户端路由刷新。
- 用户只访问一个地址，例如 `http://127.0.0.1:8000`。

API 路由必须先于前端兜底路由注册，避免静态文件处理吞掉 `/api/v1` 请求。

## 状态与错误处理

只新增原设计容许的必要状态：

- 首次加载和局部刷新；
- 无运行、无行情或无报告；
- API 不可达；
- 后端报告数据库不可用；
- 任务执行失败；
- 可重试操作。

错误信息应使用用户可理解的中文，不向页面泄露数据库 URL、密码、堆栈或内部异常详情。

## 安全边界

- `DATABASE_URL` 只存在于后端环境。
- 前端不嵌入数据库凭据、Sites 授权令牌或开发代理凭据。
- 跨域仅用于开发服务器；正式环境采用同源访问。
- 保持系统为研究辅助工具，不增加交易下单或券商控制功能。

## 验证与检查点

1. **源码检查点**：Sites V2 原始源码完整落入 `frontend/`，依赖安装和生产构建成功。
2. **视觉检查点**：六页可切换；桌面主视图逐页与 Sites V2 对照，不发生主动重设计。
3. **基础 API 检查点**：健康检查、任务类型、创建分析使用真实 FastAPI。
4. **运行数据检查点**：任务进度、行情、报告、历史记录全部使用真实 API，无生产模拟回退。
5. **单地址检查点**：FastAPI 能托管生产构建，根路径和客户端路由刷新正常，API 不被前端兜底拦截。
6. **现场检查点**：连接真实 PostgreSQL，创建任务后可从工作台、运行任务、报告和历史记录追踪同一运行。

每个检查点分别提交，上一检查点通过后才进入下一批。

## 测试策略

- 前端：API 客户端、数据映射、六页路由、加载/空/错误状态测试。
- 后端：静态托管与 SPA 回退测试，保持现有 API 与数据库测试通过。
- 构建：前端生产构建与 Python 完整测试。
- 现场验收：真实 PostgreSQL + FastAPI + 前端生产构建的端到端启动验证。

## 非目标

- 不重新设计 Sites V2。
- 不在本阶段删除 Streamlit。
- 不重建 PostgreSQL schema，除非证明确有原页面必需且无法从现有数据推导的字段。
- 不增加登录、付费、云部署或自动交易能力。
